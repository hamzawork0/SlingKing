# SlingKing R1 · M2a Catalog — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Products, variants and categories, end to end — so the owner can enter her real bag catalogue into a working Products screen.

**Architecture:** Two services in `SlingKing.Application/Catalog/` following the `AuthService` pattern — interface plus sealed implementation, `IAppDbContext` as the only database surface, no repository layer. Variants belong to the product aggregate and have no service of their own: `PUT /products/{id}` carries the whole variant list and the server diffs it inside one transaction. All 27 tables already exist from M1; this milestone adds one migration containing indexes and a check constraint, and no tables.

**Tech Stack:** .NET 8.0.408 (`net8.0`), EF Core 8.0.30, Npgsql 8.0.11, xUnit 2.9.3 + Shouldly 4.3.0; React 19.2.8, TypeScript 5.9.3, Vite 8.2.2, TanStack Query 5, React Router 7, Tailwind 4, axios.

**Spec:** `docs/superpowers/specs/2026-08-26-r1-m2a-catalog-design.md` — normative. Read it alongside this plan.

## Global Constraints

These apply to every task. Do not restate them per task; do not violate them in any task.

- **Target framework is `net8.0` everywhere.** `global.json` pins the SDK to 8.0.408.
- **`SlingKing.Domain` has zero `<ProjectReference>` and zero `<PackageReference>`.** An architecture test fails the build if this is violated. M2a adds no domain code, so nothing here should touch it.
- **Dependency direction is `Api → Application → Domain`, and `Infrastructure → Application → Domain`.** `Application` never references `Infrastructure`.
- **No secrets in source, ever.** All configuration comes from environment variables.
- **Money is `numeric(18,2)`; cost-layer unit costs are `numeric(18,4)`; quantities are `integer`; timestamps are `timestamptz` in UTC; enums are `smallint`.** Prices are **rupees with decimals, not paise** — `formatInr` takes rupees.
- **Cost is optional.** Null means *unknown*, never zero. No M2a code writes a cost.
- **Table and column names are `snake_case`;** C# properties stay `PascalCase`. `EFCore.NamingConventions` does the mapping — never hand-write `HasColumnName`.
- **Integration tests run only against the `test` schema.** The fixture throws if the connection string does not target it. Never point a test at `public`.
- **The Supabase session pooler caps this project at 15 client connections.** A test fanning out more than ~14 concurrent connections must bound its own pool via `MaxPoolSize`, never by reducing concurrency.
- **Never use the direct connection host (`db.<ref>.supabase.co`)** — it is IPv6-only and unreachable from this machine.
- **Row level security is enabled on every table with no policies.** M2a adds no tables, so there is nothing new to enable. If a task finds itself adding a table, it must also enable RLS on it. **ENABLE, never FORCE.**
- **Business logic never lives in a controller.** Controllers validate, delegate, and map to a response.
- **Internal exceptions never reach the client.** Everything becomes RFC 7807 `ProblemDetails`.
- **No deletion, anywhere.** No `DELETE` endpoint, no `Remove()` on a catalog entity. Deactivation only.
- **Validation attributes on a `record` bind to the primary-constructor parameters, not with a `[property:]` target.** A `[property:]` target compiles and then throws at request time with "validation metadata … that will be ignored". See `Contracts/Auth/AuthContracts.cs`. Do not "fix" it.
- **Commit at the end of every task**, with the message given in that task's final step.

```csharp
        await connection.OpenAsync();

    private static async Task ExecuteAsync(NpgsqlConnection connection, string sql)
    {
        await using var command = new NpgsqlCommand(sql, connection);
        await command.ExecuteNonQueryAsync();
    }

    private static async Task<long> SeedProductAsync(NpgsqlConnection connection, string code)
    {
        await using var command = new NpgsqlCommand(

              returning id;", connection);

        return (long)(await command.ExecuteScalarAsync())!;
    }

    private static string InsertVariant(long productId, string sku, string colour, bool isActive) =>
        $@"insert into product_variants
             (product_id, sku, colour, size, selling_price, low_stock_threshold,
              is_active, created_at, updated_at)
           values ({productId}, '{sku}', {colour}, null, 100, 0, {isActive.ToString().ToLower()},
                   now(), now());";

    [Fact]
    public async Task Two_active_variants_cannot_share_a_colour_and_size()
    {
        await using var connection = await OpenAsync();
        var productId = await SeedProductAsync(connection, $"PRB-{Guid.NewGuid():N}"[..12]);

        await ExecuteAsync(connection, InsertVariant(productId, $"S1-{productId}", "'Tan'", true));

        var duplicate = await Should.ThrowAsync<PostgresException>(async () =>
            await ExecuteAsync(connection, InsertVariant(productId, $"S2-{productId}", "'Tan'", true)));

        duplicate.SqlState.ShouldBe("23505");
        duplicate.ConstraintName.ShouldBe("ux_variant_combination");
    }

    /// Postgres treats every NULL as distinct, so a plain unique index would NOT catch this.
    /// The coalesce in the index definition is what makes "no colour twice" a violation.
    /// </summary>
    [Fact]
    public async Task Two_active_variants_cannot_both_have_no_colour_and_no_size()
    {
        await using var connection = await OpenAsync();
        var productId = await SeedProductAsync(connection, $"PRC-{Guid.NewGuid():N}"[..12]);

        await ExecuteAsync(connection, InsertVariant(productId, $"N1-{productId}", "null", true));

        var duplicate = await Should.ThrowAsync<PostgresException>(async () =>
            await ExecuteAsync(connection, InsertVariant(productId, $"N2-{productId}", "null", true)));

        duplicate.SqlState.ShouldBe("23505");
    }

                $"insert into categories (name, is_active, created_at) values ('{name.ToUpper()}', true, now());"));

        duplicate.SqlState.ShouldBe("23505");
    }
```

```csharp
using Microsoft.EntityFrameworkCore.Migrations;

#nullable disable

namespace SlingKing.Infrastructure.Migrations
{
    /// <summary>
    /// Three invariants that belong in the database rather than in a service.
    ///
    /// The coalesce in ux_variant_combination is load-bearing: Postgres treats every NULL as
    /// distinct, so a plain unique index on (product_id, colour, size) would happily accept
    /// ('Tan', NULL) twice. The predicate is load-bearing too — without "where is_active" a
    /// retired colour could never be reintroduced.
    ///
    /// Written as raw SQL because neither an expression index nor a partial index is
    /// expressible in the EF model, which is also why the scaffolded migration was empty.
    /// </summary>
    public partial class CatalogConstraints : Migration
    {
        /// <inheritdoc />
        protected override void Up(MigrationBuilder migrationBuilder)
        {
            migrationBuilder.Sql(@"
create unique index ux_variant_combination
    on product_variants (product_id, coalesce(colour, ''), coalesce(size, ''))
 where is_active;");

            migrationBuilder.Sql(@"
alter table product_variants
  add constraint ck_variant_threshold_non_negative
  check (low_stock_threshold >= 0);");

            migrationBuilder.Sql(@"
create unique index ux_categories_name on categories (lower(name));");
        }

        /// <inheritdoc />
        protected override void Down(MigrationBuilder migrationBuilder)
        {
            migrationBuilder.Sql("drop index if exists ux_categories_name;");
            migrationBuilder.Sql(
                "alter table product_variants drop constraint if exists ck_variant_threshold_non_negative;");
            migrationBuilder.Sql("drop index if exists ux_variant_combination;");
        }
    }
}
```

```csharp
namespace SlingKing.Application.Catalog;

/// <summary>
/// A failure the caller caused and is allowed to read about. Every message on this type is
/// written by us and carries nothing from an inner exception, a SQL fragment or a type name,
/// which is what makes it safe for <c>ProblemDetailsExceptionHandler</c> to return verbatim.
/// Anything else thrown still becomes a generic 500.
/// </summary>
public sealed class CatalogException : Exception
{
    public int StatusCode { get; }

    private CatalogException(int statusCode, string message) : base(message) =>
        StatusCode = statusCode;

    public static CatalogException NotFound(string message) => new(404, message);
    public static CatalogException Conflict(string message) => new(409, message);
    public static CatalogException Invalid(string message) => new(400, message);
}

public record CategoryOption(int Id, string Name);

/// <summary>
/// One row of the variant table as the client submits it. <c>Id</c> null means "create this
/// one"; an id means "update the one I already have". <c>IsActive</c> is explicit and is
/// never inferred from a row's absence — a variant missing from the list is left untouched,
/// because "missing means delete" is how this pattern silently destroys data.
/// </summary>
public record VariantInput(
    long? Id,
    string? Colour,
    string? Size,
    decimal SellingPrice,
    int LowStockThreshold,
    bool IsActive);

public record ProductInput(
    string Name,
    int? CategoryId,
    string? Description,
    IReadOnlyList<VariantInput> Variants);

public record VariantView(
    long Id,
    string Sku,
    string? Colour,
    string? Size,
    decimal SellingPrice,
    int LowStockThreshold,
    bool IsActive,
    int PhysicalQty);

/// <summary>
/// <c>TotalStock</c> is always 0 until M2b, because nothing can move stock yet. It is read
/// from real <c>stock_levels</c> rows rather than synthesised, which is what the eager
/// zero-quantity rows written at creation buy.
/// </summary>
public record ProductView(
    long Id,
    string Code,
    string Name,
    int? CategoryId,
    string? CategoryName,
    string? Description,
    bool IsActive,
    int TotalStock,
    IReadOnlyList<VariantView> Variants);
```

```csharp
using Microsoft.EntityFrameworkCore;
using SlingKing.Application.Common.Abstractions;
using SlingKing.Domain.Catalog;

namespace SlingKing.Application.Catalog;

public sealed class CategoryService : ICategoryService
{
    private readonly IAppDbContext _db;
    private readonly IClock _clock;

    public CategoryService(IAppDbContext db, IClock clock)
    {
        _db = db;
        _clock = clock;
    }

    public async Task<IReadOnlyList<CategoryOption>> ListAsync(
        CancellationToken cancellationToken = default) =>
        await _db.Categories
            .Where(c => c.IsActive)
            .OrderBy(c => c.Name)
            .Select(c => new CategoryOption(c.Id, c.Name))
            .ToListAsync(cancellationToken);

    public async Task<CategoryOption> CreateAsync(
        string name, CancellationToken cancellationToken = default)
    {
        var trimmed = name.Trim();

        // ux_categories_name is the real guarantee; this check exists only to turn the
        // race's loser into a readable 409 instead of a 500 from a constraint violation.
        var taken = await _db.Categories
            .AnyAsync(c => c.Name.ToLower() == trimmed.ToLower(), cancellationToken);

        if (taken)
        {
            throw CatalogException.Conflict($"A category named \"{trimmed}\" already exists.");
        }

        var category = new Category
        {
            Name = trimmed,
            IsActive = true,
            CreatedAt = _clock.UtcNow
        };

        _db.Categories.Add(category);
        await _db.SaveChangesAsync(cancellationToken);

        return new CategoryOption(category.Id, category.Name);
    }
}
```

```csharp
        if (exception is CatalogException rejected)
```

```csharp
using Microsoft.EntityFrameworkCore;
using SlingKing.Application.Common.Abstractions;
using SlingKing.Domain.Catalog;
using SlingKing.Domain.Inventory;

namespace SlingKing.Application.Catalog;

public sealed class ProductService : IProductService
{
    private readonly IAppDbContext _db;
    private readonly INumberSequenceAllocator _sequences;
    private readonly IClock _clock;

    public ProductService(
        IAppDbContext db, INumberSequenceAllocator sequences, IClock clock)
    {
        _db = db;
        _sequences = sequences;
        _clock = clock;
    }

    /// <summary>Blank and whitespace collapse to null, so "" and null cannot both exist.</summary>
    private static string? Normalise(string? value) =>
        string.IsNullOrWhiteSpace(value) ? null : value.Trim();

    private static void RejectDuplicateCombinations(IReadOnlyList<VariantInput> variants)
    {
        var seen = new HashSet<(string, string)>();

        foreach (var variant in variants.Where(v => v.IsActive))
        {
            var key = (Normalise(variant.Colour)?.ToLowerInvariant() ?? "",
                       Normalise(variant.Size)?.ToLowerInvariant() ?? "");

            if (!seen.Add(key))
            {
                throw CatalogException.Conflict(
                    "Two variants have the same colour and size. Each combination may appear once.");
            }
        }
    }

    private static void RejectInvalidVariants(IReadOnlyList<VariantInput> variants)
    {
        foreach (var variant in variants)
        {
            if (variant.SellingPrice < 0)
            {
                throw CatalogException.Invalid("A selling price cannot be negative.");
            }

            if (variant.LowStockThreshold < 0)
            {
                throw CatalogException.Invalid("A low stock threshold cannot be negative.");
            }
        }
    }

    private async Task RequireKnownCategoryAsync(int? categoryId, CancellationToken cancellationToken)
    {
        if (categoryId is null)
        {
            return;
        }

        var exists = await _db.Categories
            .AnyAsync(c => c.Id == categoryId && c.IsActive, cancellationToken);

        if (!exists)
        {
            throw CatalogException.Invalid("That category does not exist.");
        }
    }

    private Task<int> DefaultLocationIdAsync(CancellationToken cancellationToken) =>
        _db.Locations.Where(l => l.IsDefault).Select(l => l.Id).SingleAsync(cancellationToken);

    public async Task<ProductView?> GetAsync(long id, CancellationToken cancellationToken = default)
    {
        var product = await _db.Products
            .AsNoTracking()
            .Where(p => p.Id == id)
            .Select(p => new
            {
                p.Id, p.Code, p.Name, p.CategoryId, p.Description, p.IsActive,
                CategoryName = p.Category == null ? null : p.Category.Name
            })
            .SingleOrDefaultAsync(cancellationToken);

        if (product is null)
        {
            return null;
        }

        // Left join onto stock_levels so a variant whose row is somehow missing reads 0
        // rather than vanishing from the response.
        var variants = await _db.ProductVariants
            .AsNoTracking()
            .Where(v => v.ProductId == id)
            .OrderBy(v => v.Sku)
            .Select(v => new VariantView(
                v.Id, v.Sku, v.Colour, v.Size, v.SellingPrice, v.LowStockThreshold, v.IsActive,
                _db.StockLevels.Where(s => s.VariantId == v.Id).Sum(s => (int?)s.PhysicalQty) ?? 0))
            .ToListAsync(cancellationToken);

        return new ProductView(
            product.Id, product.Code, product.Name, product.CategoryId, product.CategoryName,
            product.Description, product.IsActive,
            variants.Where(v => v.IsActive).Sum(v => v.PhysicalQty),
            variants);
    }

    public async Task<ProductView> CreateAsync(
        ProductInput input, CancellationToken cancellationToken = default)
    {
        await RequireKnownCategoryAsync(input.CategoryId, cancellationToken);

        // No variations is a legitimate answer, not a missing one. Stock lives at variant
        // level, so a product with no variant could never hold stock.
        var requested = input.Variants.Count > 0
            ? input.Variants
            : [new VariantInput(null, null, null, 0m, 0, true)];

        RejectInvalidVariants(requested);
        RejectDuplicateCombinations(requested);

        var now = _clock.UtcNow;
        var defaultLocationId = await DefaultLocationIdAsync(cancellationToken);

        await using var transaction = await _db.Database.BeginTransactionAsync(cancellationToken);

        // Inside the transaction on purpose: the allocator's UPDATE rolls back with
        // everything else, so a failed create returns its number to the sequence.
        var code = await _sequences.NextAsync("product", cancellationToken);

        var product = new Product
        {
            Code = code,
            Name = input.Name.Trim(),
            CategoryId = input.CategoryId,
            Description = Normalise(input.Description),
            IsActive = true,
            CreatedAt = now,
            UpdatedAt = now
        };

        _db.Products.Add(product);
        await _db.SaveChangesAsync(cancellationToken);

        var variants = requested.Select((variant, index) => new ProductVariant
        {
            ProductId = product.Id,
            Sku = $"{code}-V{index + 1:00}",
            Colour = Normalise(variant.Colour),
            Size = Normalise(variant.Size),
            SellingPrice = variant.SellingPrice,
            LowStockThreshold = variant.LowStockThreshold,
            IsActive = true,
            CreatedAt = now,
            UpdatedAt = now
        }).ToList();

        _db.ProductVariants.AddRange(variants);
        await _db.SaveChangesAsync(cancellationToken);

        foreach (var variant in variants)
        {
            _db.StockLevels.Add(new StockLevel
            {
                VariantId = variant.Id,
                LocationId = defaultLocationId,
                PhysicalQty = 0,
                ReservedQty = 0,
                UpdatedAt = now
            });
        }

        await _db.SaveChangesAsync(cancellationToken);
        await transaction.CommitAsync(cancellationToken);

        return (await GetAsync(product.Id, cancellationToken))!;
    }
}
```

```csharp
    public async Task<IReadOnlyList<ProductView>> ListAsync(
        string? search,
        bool includeInactive,
        CancellationToken cancellationToken = default)
    {
        var query = _db.Products.AsNoTracking();

        if (!includeInactive)
        {
            query = query.Where(p => p.IsActive);
        }

        if (!string.IsNullOrWhiteSpace(search))
        {
            var term = $"%{search.Trim()}%";

            // ILike is Npgsql's case-insensitive LIKE and translates to SQL. ToLower() on
            // both sides would work too but defeats any index we add later.
            query = query.Where(p =>
                EF.Functions.ILike(p.Name, term) ||
                EF.Functions.ILike(p.Code, term) ||
                p.Variants.Any(v => EF.Functions.ILike(v.Sku, term)));
        }

        var ids = await query
            .OrderByDescending(p => p.Id)
            .Select(p => p.Id)
            .ToListAsync(cancellationToken);

        // ponytail: N+1 by construction — one GetAsync per product. Fine for a catalogue of
        // a few hundred bags on a single-user system. Replace with one projected query if
        // the list ever feels slow.
        var products = new List<ProductView>(ids.Count);

        foreach (var id in ids)
        {
            var product = await GetAsync(id, cancellationToken);

            if (product is not null)
            {
                products.Add(product);
            }
        }

        return products;
    }
```

```csharp
    public async Task<ProductView> UpdateAsync(
        long id, ProductInput input, CancellationToken cancellationToken = default)
    {
        var product = await _db.Products
            .Include(p => p.Variants)
            .SingleOrDefaultAsync(p => p.Id == id, cancellationToken)
            ?? throw CatalogException.NotFound("That product does not exist.");

        await RequireKnownCategoryAsync(input.CategoryId, cancellationToken);
        RejectInvalidVariants(input.Variants);

        var known = product.Variants.ToDictionary(v => v.Id);

        foreach (var row in input.Variants.Where(r => r.Id is not null))
        {
            if (!known.ContainsKey(row.Id!.Value))
            {
                throw CatalogException.Invalid(
                    "A variant in the request does not belong to this product.");
            }
        }

        // The combination check must consider the product's whole active picture after the
        // edit, not just the rows in the payload — an untouched variant still occupies its
        // colour. Rows the payload does not mention keep whatever state they already had.
        var mentioned = input.Variants
            .Where(r => r.Id is not null)
            .Select(r => r.Id!.Value)
            .ToHashSet();

        var resulting = input.Variants
            .Concat(product.Variants
                .Where(v => !mentioned.Contains(v.Id))
                .Select(v => new VariantInput(
                    v.Id, v.Colour, v.Size, v.SellingPrice, v.LowStockThreshold, v.IsActive)))
            .ToList();

        RejectDuplicateCombinations(resulting);

        var now = _clock.UtcNow;
        var defaultLocationId = await DefaultLocationIdAsync(cancellationToken);

        await using var transaction = await _db.Database.BeginTransactionAsync(cancellationToken);

        product.Name = input.Name.Trim();
        product.CategoryId = input.CategoryId;
        product.Description = Normalise(input.Description);
        product.UpdatedAt = now;

        // Ordinals come from the count of every variant ever created for this product,
        // active or not. Variants are never removed, so the count only grows and an ordinal
        // is never reused.
        var ordinal = product.Variants.Count;
        var created = new List<ProductVariant>();

        foreach (var row in input.Variants)
        {
            if (row.Id is not null)
            {
                var existing = known[row.Id.Value];
                existing.Colour = Normalise(row.Colour);
                existing.Size = Normalise(row.Size);
                existing.SellingPrice = row.SellingPrice;
                existing.LowStockThreshold = row.LowStockThreshold;
                existing.IsActive = row.IsActive;
                existing.UpdatedAt = now;
                continue;
            }

            ordinal++;

            var variant = new ProductVariant
            {
                ProductId = product.Id,
                Sku = $"{product.Code}-V{ordinal:00}",
                Colour = Normalise(row.Colour),
                Size = Normalise(row.Size),
                SellingPrice = row.SellingPrice,
                LowStockThreshold = row.LowStockThreshold,
                IsActive = row.IsActive,
                CreatedAt = now,
                UpdatedAt = now
            };

            _db.ProductVariants.Add(variant);
            created.Add(variant);
        }

        await _db.SaveChangesAsync(cancellationToken);

        foreach (var variant in created)
        {
            _db.StockLevels.Add(new StockLevel
            {
                VariantId = variant.Id,
                LocationId = defaultLocationId,
                PhysicalQty = 0,
                ReservedQty = 0,
                UpdatedAt = now
            });
        }

        await _db.SaveChangesAsync(cancellationToken);
        await transaction.CommitAsync(cancellationToken);

        return (await GetAsync(id, cancellationToken))!;
    }
```

```tsx
import { CategorySelect } from "./CategorySelect";

  colour: "",
  size: "",
  sellingPrice: 0,
  lowStockThreshold: 0,
  isActive: true,
};

  name: "",
  categoryId: null,
  description: "",
  variants: [blankVariant],
};

const field =
  "mt-1.5 w-full rounded-stamp border border-rule bg-panel px-3 py-2.5 text-[14px] " +
  "transition-colors placeholder:text-muted/60 focus:border-saddle";

export function ProductForm() {
  const { id } = useParams();
  const productId = id ? Number(id) : null;
  const navigate = useNavigate();
  const queryClient = useQueryClient();

  const [form, setForm] = useState<ProductPayload>(emptyProduct);
  const [skus, setSkus] = useState<Record<number, string>>({});
  const [code, setCode] = useState<string | null>(null);
  const [error, setError] = useState<string | null>(null);

  const existing = useQuery({
    queryKey: ["product", productId],
    queryFn: () => getProduct(productId!),
    enabled: productId !== null,
  });

  useEffect(() => {
    if (!existing.data) return;

    setForm(toPayload(existing.data));
    setCode(existing.data.code);
    setSkus(Object.fromEntries(existing.data.variants.map((v) => [v.id, v.sku])));
  }, [existing.data]);

  const save = useMutation({
    mutationFn: (payload: ProductPayload) =>
      productId === null ? createProduct(payload) : updateProduct(productId, payload),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["products"] });
      navigate("/products");

        isNetworkError(err)
          ? "Cannot reach the server. Check your connection and try again."
          : "That could not be saved. Check that each colour and size appears only once.",
      ),

      ...current,

        ...v,
        colour: v.colour?.trim() || null,
        size: v.size?.trim() || null,
      })),

      <form onSubmit={handleSubmit} className="mt-6">
        <label className="text-[12px] font-medium tracking-wide" htmlFor="name">
          Name
        </label>
        <input
          id="name"
          required
          value={form.name}
          onChange={(e) => setForm({ ...form, name: e.target.value })}
          className={field}
        />

        <div className="mt-4">
          <span className="text-[12px] font-medium tracking-wide">Category</span>
          <CategorySelect

            onChange={(categoryId) => setForm({ ...form, categoryId })}
          />
        </div>

          <label className="text-[12px] font-medium tracking-wide" htmlFor="description">
            Description
          </label>
          <textarea
            id="description"
            rows={3}
```

## Self-Review

**Spec coverage.** Every section of the spec maps to a task: constraints migration → Task 1; models, error mapping, categories → Task 2; create → Task 3; list and search → Task 4; update with variant diff → Task 5; deactivate and the no-delete proof → Task 6; frontend API → Task 7; list screen → Task 8; form and inline categories → Task 9; shell and browser walkthrough → Task 10; gate → Task 11. The four "semantics fixed here" clauses in the spec are each pinned by a test: `includeInactive` (Task 6 Step 1), untouched variant states on deactivate (Task 6 Step 1), code and SKU immutability (Task 5 Step 1 and Task 7 Step 1), `totalStock` always 0 (Task 3 Step 2).

**One deliberate deviation from the spec**, recorded here rather than silently: the spec writes `ux_variant_combination` as an unconditional unique index. This plan makes it **partial on `is_active`**. Unconditional, retiring "Tan" would permanently forbid ever selling a Tan of that product again, because the retired row keeps occupying the combination. The real invariant is "at most one *active* variant per colour and size". Task 1 Step 1 tests exactly that, and Task 5 pins the consequence.

**Type consistency.** `ProductView`, `VariantView`, `VariantInput` and `ProductInput` are defined once in Task 2 and used unchanged in Tasks 3–6; the TypeScript mirrors in Task 7 match field for field, in camelCase as System.Text.Json emits them. `CreateAsync` and `UpdateAsync` both take `ProductInput` — there is no separate create/update input type, which is why `VariantInput.Id` is nullable.
